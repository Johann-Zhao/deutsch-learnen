## 1. 项目现状评估

### 1.1 项目是什么

一个**纯静态、零依赖的浏览器端德语学习应用**（A1–B1），双击 `index.html` 即可运行，
无服务器、无构建工具、无框架。数据存于 `localStorage`（key: `deA1.progress.v1`）。

### 1.2 技术栈

| 层级 | 现状 |
|------|------|
| 语言 | 原生 HTML/CSS/JS（IIFE 模块风格，全局变量通信） |
| 路由 | Hash 路由（`#/vocab`、`#/learn` …） |
| 持久化 | `localStorage` |
| 算法 | 自实现 FSRS-4.5（`js/srs.js`），兼容 SM-2 迁移 |
| 测试 | Node 原生 `assert`，31 项单元测试（`tests/run.js`） |
| 内容生产 | Python 脚本：edge-tts 生成音频、Wikimedia/Openverse 抓图、Seedream 生成封面 |
| 音频回退 | 浏览器 `speechSynthesis` |

### 1.3 内容与功能规模

| 维度 | 数量 |
|------|------|
| 词汇 | 1945 词（A1 618 / A2 612 / B1 715），38 个主题 |
| 语法专题 | 36 个（A1 10 / A2 12 / B1 14），259 道练习题 |
| 音频 | 单词 1945 + 例句 1945 + 变位 251 |
| 图片 | 主题封面 38 + 词条配图 1092 |
| 已实现功能 | 仪表盘、级别切换、百词斩式四步学新词、5 题型 SRS 复习、错题本、语法讲解+练习、动词变位查询、打卡/连胜/冻结券、设置与导入导出 |

### 1.4 核心优势（要保住）

1. **FSRS-4.5 已正确实现且有测试**——这是大多数竞品（SM-2 级别）都没有的算法优势。
2. **内容扎实且离线完整**——1945 词全部带音频、1092 张配图、授权信息完备（`images/credits.json`）。
3. **词性三色系统**贯穿卡片/例句/反馈，是有效的德语专属记忆辅助。
4. **答案匹配做了德语的脏活**：大小写、`ä/ö/ü/ß` ↔ `ae/oe/ue/ss`、冠词可选（`js/srs.js` 的 `matches`）。
5. **零门槛运行**：无构建、无安装，这是部署和分发上的巨大优势。
6. **有 `DESIGN.md` 设计规范**，UI 一致性有约束。

### 1.5 主要短板（按严重程度排序）

| # | 短板 | 影响 | 位置 |
|---|------|------|------|
| 1 | 只有词汇+语法，**没有听力、阅读、口语** | 学习维度单一，留不住进阶用户 | 全局 |
| 2 | `localStorage` 单点存储 | 清缓存/换设备丢进度；5MB 上限 | `js/storage.js` |
| 3 | 无模块系统/构建工具，全局变量污染 | 协作与长期维护困难 | 全站 |
| 4 | 首屏加载全部数据（含 B1），无懒加载 | 内容再增长会拖慢首屏 | `index.html` |
| 5 | 语法错题**不进入 SRS**，只记错题本 | 语法掌握无间隔重复保障 | `js/grammar.js` |
| 6 | 无 PWA | 不能像 App 一样安装到手机桌面、离线推送 | — |
| 7 | 无 UI/集成测试 | 重构页面交互无安全网 | `tests/run.js` |
| 8 | 内容生产脚本耦合外部 API 和硬编码路径 | 换环境跑不起来（如 `tools/gen_covers.py` 读 `E:\LabX\backend\.env`） | `tools/` |
| 9 | 媒体资源体积大（数千 MP3+图片） | 不利于网络分发和 PWA 缓存 | `audio/`、`images/` |
| 10 | `stripArticle` 把 `to/zu` 当冠词去掉，答案判定偶尔过宽 | 少量误判 | `js/srs.js:104` |

## 2. 市场调研：竞品设计精华

### 2.1 竞品一句话画像

| 产品 | 核心打法 | 对本项目的启示 |
|------|----------|----------------|
| **Duolingo** | 单一路径 + 游戏化（连胜/XP/排行榜），3–5 分钟一节课，DAU 十年十倍 | 路径化降低决策疲劳；先学后注册使次日留存 +20% |
| **Babbel** | 成人向对话驱动课程 + Review Manager（SRS），为学习者母语定制解释 | 语法提示以「短贴士」嵌入练习，不要长篇大论 |
| **Busuu** | 明确 CEFR 对齐 + 母语者社区纠错 | CEFR 标签本身就是德语学习者的强动机 |
| **Memrise** | 母语者短视频 + 间隔重复 | 视频建立「声音-情境-情感」强记忆关联 |
| **Anki** | 工具化闪卡 + FSRS（24.11 起默认）+ `.apkg` 生态 | FSRS 已被主流验证；`.apkg` 是闪卡交换事实标准 |
| **Nicos Weg (DW)** | 电视剧级免费视频课，A1–B1 三季线性剧情 | 剧情连续性提供「追更」动机；短板是无输出练习 |
| **Seedlang** | 每词每句都是母语者视频 + 点击字幕查语法 + 录音对比 | 「点击任意词即时查义+语法」极大降低阅读认知负荷 |
| **Clozemaster** | Tatoeba 真实句子 cloze 填词，按词频组织 | B1+ 词汇高原突破利器，开发成本低 |
| **LingQ** | 可理解输入阅读：点词标记→SRS | 阅读即学习的工作流标杆，但 UI 信息过载被诟病 |
| **德语助手** | 词典为核 + 生词本 + 跨软件取词 + 变位查询 | 工具入口（查词）可以成为学习入口 |

### 2.2 被广泛验证有效的设计（应该抄）

按性价比排序：

1. **单一路径 + 小步快跑**：下一步学什么不需要用户决定；每节课 3–5 分钟。
2. **连胜（Streak）+ 冻结券**：本项目已实现 ✅，且冻结券（每 7 天补 1 张）与 Duolingo 的 Streak Freeze 同思路，是正确设计。
3. **SRS 间隔重复**：本项目已实现 FSRS ✅，且优于多数竞品的 SM-2。
4. **真实语境中的词汇**：例句 cloze、点词查义，避免孤立背单词。
5. **CEFR 分级标签**：本项目已实现 A1/A2/B1 切换 ✅，但应进一步标注「学完本级别≈通过歌德 A1」。
6. **即时反馈 + 错题回流**：本项目已实现 ✅。
7. **母语者音频/视频**：本项目单词/例句音频已预生成 ✅（edge-tts 神经语音，质量足够；真人口型视频不必追）。

### 2.3 不值得抄的设计

- **排行榜/联赛**：个人项目用户基数小，鬼服排行榜反而打击动力。
- **过度游戏化（生命值、能量条、广告卡点）**：定位为「严肃高效自学」时损害信任。
- **UGC 内容平台**：内容审核与运营成本个人开发者扛不住（Memrise 2023 年已收缩官方课程）。
- **AI 视频通话陪练**：成本高、体验仍是脚本化，现阶段不必追。
- **LingQ 式大而全阅读库**：内容维护成本极高，UI 复杂度是反面教材。

### 3.2 2024–2026 年开源新趋势（本项目可对齐）

- **本地优先（local-first）**：数据落本地（SQLite/IndexedDB），云端只做可选同步——与本项目的纯静态哲学一致。
- **硬编码课程骨架 + AI 按需生成**：课程内容保证路径稳定，解释/对话/批改由 AI 补——适合本项目未来接入 LLM 功能（见 §10.4）。
- **AI 功能走服务端代理**：API key 绝不进客户端（Deutschy 用 Node 代理 Gemini）。

## 5. 差距分析：现状 vs 标杆

| 能力 | 本项目 | 标杆 | 差距 |
|------|--------|------|------|
| 词汇学习 | 四步流程 + 配图 + 音频 | 百词斩/Memrise | **已持平**，记忆链路完整 |
| 复习算法 | FSRS-4.5 | Anki FSRS | **已持平甚至领先**多数竞品 |
| 语法学习 | 讲解 + 一次性练习 | Babbel | 缺：错题进 SRS、语法点与词汇联动 |
| 听力 | ❌ 无 | Nicos Weg / Seedlang | **最大空白** |
| 阅读 | ❌ 无 | LingQ / Lute | **第二大空白** |
| 口语 | ❌ 无 | Seedlang 录音对比 | 空白，但可用 Whisper 低成本补齐 |
| 写作 | ❌ 无 | Busuu 社区批改 | 可暂缓（或未来接 LLM 批改） |
| 激励系统 | 连胜+冻结券+成就 | Duolingo | **已够用**，不追排行榜 |
| 多端同步 | ❌ 无 | 所有商业产品 | 中长期短板 |
| 移动端体验 | 响应式网页 | 原生 App | 加 PWA 可覆盖 80% 场景 |
| 数据安全 | localStorage 单点 | SQLite + 云备份 | 需尽快升级 IndexedDB |

**结论**：本项目在「词汇+语法+复习」三角已经做到个人开发者的一流水准。
差距集中在三点：**输入维度（听/读）缺失、数据持久化脆弱、工程化基础设施薄弱**。

## 6. 改进方向与优先级

> 原则：**先做不破坏「双击即用」优势的改进，架构演进走增量路线，不搞一次性重写。**

### P0 — 立刻做（低风险高回报，不动架构）

1. **语法错题纳入 SRS**：复用现有 FSRS，把语法错题当作独立卡片调度（§8.2）。
2. **存储层换 IndexedDB**：在 `js/storage.js` 内部换实现，对外 API 不变；保留 localStorage 作迁移来源和回退（§7.1）。
3. **数据懒加载**：`index.html` 只加载当前级别的 `vocabulary_*.js` / `grammar_*.js`，切级别时动态 `<script>` 注入（§7.2）。
4. **修 `stripArticle` 误判**：`js/srs.js:104` 不应剥离 `to/zu`。

### P1 — 本季度做（新学习维度）

5. **听力模块**：用现有 1945 条例句音频 + edge-tts/Piper 生成短文音频，做「听写→选择→跟读」三级练习（§10.1）。
6. **阅读模块**：导入短文本 → 点词查义（接 Kaikki 离线词典）→ 生词一键进 SRS（§10.2）。
7. **PWA 化**：manifest + Service Worker，手机桌面安装、离线缓存、每日学习提醒通知（§7.3）。

### P2 — 半年内做（体验与规模）

8. **词库扩充管道**：Kaikki + Tatoeba + Leipzig 词频 → 半自动生成新词条（§9.2）。
9. **动词变位数据升级**：接入 german-verbs-database（8000+ 词），替换规则推导 + 30 词硬编码。
10. **内容生产脚本工程化**：环境变量配置化，去掉 `E:\LabX` 硬编码（§9.3）。

### P3 — 长期（视目标决定）

11. **口语跟读评分**：whisper.cpp WASM 本地识别（§10.3）。
12. **可选云同步 + LLM 功能**（写作批改、AI 对话）：届时再引入后端（§7.4、§10.4）。

### 明确不做

- 排行榜/联赛、UGC 平台、AI 视频陪练、原生 App 重写（理由见 §2.3）。

## 7. 架构演进方案

### 7.1 第一阶段：存储升级（不改对外 API）

`js/storage.js` 当前是 `localStorage` 的薄封装。改造方案：

```
storage.js 公开 API 保持不变（store.state / save() / touchToday() …）
    └── 内部实现换成 IndexedDB（库名 deA1，单 objectStore: kv）
        ├── 启动时：IndexedDB 为空但 localStorage 有数据 → 一次性迁移
        ├── 写策略：防抖 300ms 落盘（现在每次操作都同步序列化整个 JSON）
        └── localStorage 保留只读镜像 30 天，作为迁移回退
```

理由：IndexedDB 容量从 ~5MB 升到数百 MB（存音频缓存也够）、异步不阻塞 UI、
天然支持事务。**不要引入 Dexie 等依赖**——单 objectStore 的 KV 用原生 API 不到 80 行。

### 7.2 第二阶段：构建与模块化（渐进，不重写）

当前「无构建」是优势也是瓶颈。折中方案——**引入 esbuild 只做打包，不引入框架**：

```
德语学习项目/
├── src/                    # 原 js/ 迁入，逐个文件从 IIFE 改成 ES Module
│   ├── app.js  srs.js  storage.js  vocabulary.js  ...
├── data/                   # 不动，仍是全局数据文件，但改为按级别动态加载
├── scripts/build.mjs       # esbuild --bundle --splitting
└── dist/                   # 产物，index.html 引用 dist/app.js
```

- **为什么 esbuild 而不是 Vite/webpack**：零配置、单文件、打包快，符合项目极简气质。
- **ES Module 化的收益**：消灭 `window.VOCAB_THEMES` 这类全局污染，测试可以 `import` 而不是 UMD 兼容层。
- **代码分割**：`esbuild --splitting` + 动态 `import()`，实现按级别（A1/A2/B1）懒加载数据，
  首屏只下当前级别。
- **过渡期**：保留无构建版本在 `legacy/` 分支，确认打包版稳定后再切换。

**明确不做的**：不迁 React/Vue。当前 UI 复杂度（十几个视图、表单驱动）用原生 DOM 模板完全够，
引入框架的收益抵不上重写成本和包体积。如果未来做阅读/听力后发现 DOM 代码失控，
再评估 htmx/petite-vue 这类轻量方案。

### 7.3 第三阶段：PWA

```
新增文件：
├── manifest.webmanifest    # 名称、图标、theme_color、display: standalone
├── sw.js                   # Service Worker：预缓存核心 JS/CSS + 运行时缓存音频/图片
└── icons/                  # 192/512 图标
```

- **缓存策略**：JS/CSS/HTML → CacheFirst + 版本号刷新；`audio/` `images/` → CacheFirst 永不主动失效（内容地址不可变）；数据文件 → NetworkFirst。
- **媒体体积对策**：不要预缓存 4000+ 音频。只缓存「当前级别 + 本周到期复习词」的音频，其余按需缓存。
- **音频压缩**：现有 MP3 若是 128kbps+，批量转 48–64kbps（语音完全够），预计体积减半以上：`ffmpeg -i in.mp3 -b:a 56k -ar 22050 out.mp3`。
- **每日提醒**：PWA 通知在 Android 可用；iOS  Safari 16.4+ 支持但需用户授权，作为增强而非依赖。

### 7.4 第四阶段（可选）：后端与同步

只有当「多端同步」成为真实需求时才做：

- **最小方案**：不建账号系统，用「同步码」——导出加密 JSON 到 WebDAV/网盘（参考 LingKuma 的 WebDAV 同步），零服务器成本。
- **完整方案**：Cloudflare Workers + D1（SQLite）或 Supabase 免费层，匿名设备 ID + 进度 JSON 同步。LLM 功能（批改/对话）也必须经此代理，API key 不出服务端。
- **本地优先原则不变**：离线永远是完整可用的，云只是备份和同步介质。

## 8. 学习逻辑改进

### 8.1 FSRS 现状已好，做两个微调

1. **独立化词汇与语法的调度参数**：语法题的错误模式不同于词汇（更偏理解而非遗忘），
   长期可考虑为语法卡片单独训一组 FSRS 权重；短期不用动，17 个默认参数即可。
2. **`mastered` 阈值可配置**：当前稳定度 ≥21 天即掌握（`js/srs.js`）。建议设置页暴露
   目标保留率（如 0.9），由保留率反推掌握阈值，而不是硬编码天数。

### 8.2 语法错题进 SRS（P0，本周就能做）

现状：`js/grammar.js` 做错只写 `mistakes`，不会再被调度。改法：

```
1. 每道语法练习生成稳定卡片 ID：`{topicId}#{exerciseIndex}`（现在错题本已在用这个 ID，直接复用）
2. 答错 → DeSRS.review(cardId, quality=0)；答对 → quality=2
3. 「今日复习」页面混入到期的语法卡（与词汇卡分开展示，标注「语法」徽章）
4. 复习呈现：直接重放原题（题干+选项已存在数据里，零新内容成本）
```

这是全项目**性价比最高的一刀**：数据在、算法在、UI 在，只差接线。

### 8.3 词汇网络：从「主题」到「织网」

现状 38 个主题是并列孤岛。标杆产品的经验是词汇要成网：

- **词族联动**：学 `fahren` 时提示已学的 `die Fahrt / der Fahrer / abfahren`（Kaikki 数据自带词族关系）。
- **搭配（Kollokationen）**：`eine Entscheidung treffen` 这类动名搭配是 B1 考试核心，
  词条结构加可选 `collocations: []` 字段。
- **近义/反义**：复习题干扰项从「同主题随机词」升级为「近义词优先」——显著提高区分度训练。
- **复合词拆分**：german-nouns 的复合词拆分数据可做「猜复合词词义」小游戏（德语特色，竞品少有）。

### 8.4 每日节奏编排（对齐 Duolingo 路径思想）

当前仪表盘已有任务卡片，升级为明确的**今日路径**：

```
今日学习单（自动生成，顺序执行）：
  ① 复习到期卡片（SRS，硬上限 30 个）   ← 复习优先，防遗忘债
  ② 学新词 N 个（设置页可调，默认 10）
  ③ 语法 1 个专题（新授 或 错题复习，交替）
  ④ 听力/阅读 1 篇（新模块上线后）
  → 完成 ①② 即算打卡（保连胜），③④ 为加分项
```

设计依据：Duolingo 的「无需决策的下一步」+ Nicos Weg 的线性推进。
全部完成显示成就动效（动效规范已在 `DESIGN.md`）。

## 9. 内容建设规划

### 9.1 现状内容的缺口

- 1945 词覆盖 A1–B1 合格，但对照 Goethe B1 词表（约 2400 词）和「B1→B2 过渡期」仍有缺口。
- 例句每词 1 条，标杆是 2–3 条（一条简单 + 一条真实语境）。
- 缺 B2 级别（若目标用户是留德/德福方向，B2 是刚需；若是兴趣方向，B1 封顶合理——**这是产品决策，建议先在 README 写明定位**）。

### 9.2 词条半自动生产管道

在 `tools/` 新增 `build_vocab.py`，数据源全部来自 §4.1 的许可安全清单：

```
输入：目标词表（现有词 + Kaikki 高频词过滤出 B2 候选）
管道：
  1. Kaikki JSON  → 抽取：词性、性别、复数、IPA、变位
  2. Tatoeba      → 按句长 5–15 词、含目标词、有德中翻译 过滤 2 条例句
  3. Leipzig 词频 → 给每个词打 frequency rank，用于排序和分级校验
  4. DeepL Free   → 翻译缺失的中文释义（人工抽检 10%）
  5. Piper/edge-tts → 生成新词音频（命名规则沿用现有 word/{id}.mp3）
  6. 输出         → data/vocabulary_b2.js 同格式文件 + 更新 manifest
人工环节：主题归类、释义润色、配图挑选（管道给出 3 张候选图）
```

**关键原则：管道生成草稿，人做终审。** 现有 1945 词的质量（释义准确度、例句贴切度）
是产品口碑的来源，不要被自动化稀释。

### 9.3 内容生产脚本工程化

- `tools/` 全部脚本改为读 `.env`（`python-dotenv`），删除 `E:\LabX\backend\.env` 硬编码。
- 加 `tools/README.md`：每个脚本的用途、依赖、运行顺序。
- 加 `requirements.txt` 锁版本（edge-tts、httpx、python-dotenv）。
- manifest 生成脚本化（现在 `audio/manifest.js`、`images/manifest.js` 是 AUTO 生成但没有统一入口）。

## 10. 新功能模块设计

### 10.1 听力模块（P1）

**内容策略——零版权风险路线**：不写不录长文章，用现有资产组合：

| 题型 | 内容来源 | 说明 |
|------|----------|------|
| 单词听写 | 现有 1945 词音频 | 已存在于 SRS 题型，归入听力 Tab |
| 例句听写 | 现有 1945 条例句音频 | 已存在于 SRS 题型，加强化训练入口 |
| 小对话 | Tatoeba 句对拼接 + TTS 分角色朗读 | 3–5 轮对话，听主旨/细节选择题 |
| 慢速短文 | 用已学词汇写 80–120 词短文（人工+LLM 辅助），TTS 生成 | 「可理解输入」i+1 原则：只含已学词 + 5% 新词 |

**交互三级**：先盲听 → 看题作答 → 对照原文逐句精听（点句重播）。
**进阶**：语速 0.75×/1×/1.25× 已有基础设施（设置页 ttsRate），直接复用。

### 10.2 阅读模块（P1）

Lute 工作流的极简版：

```
导入/选择文本（内置分级短文库 + 用户粘贴）
  → 分词渲染（德语按空格+复合词规则，可用 german-nouns 的拆分数据）
  → 每个词三态着色：已掌握(无色) / 学习中(黄) / 生词(蓝)  —— 颜色值遵守 DESIGN.md
  → 点击生词：弹出卡片（释义/词性/发音/例句），数据源 = 本项目词库 ∪ Kaikki 离线词典
  → 「加入学习」一键进 SRS
  → 底部统计：本文生词率（>10% 提示「这篇太难了」）
```

内容来源：自写短文（同 §10.1 慢速短文复用）+ 用户自粘贴（任何网页文字）。
**不要内置新闻抓取**——RSS 全文有版权问题，让用户自己粘贴即可。

### 10.3 口语跟读（P3，技术验证先行）

- **方案**：whisper.cpp 编译 WASM 在浏览器本地跑（tiny/base 模型约 40–80MB，德语准确率可接受）。
- **流程**：听原句 → 录音 → 本地识别 → 与原文按词对齐标红 → 重录。
- **不做打分百分比**（伪精确），只做「识别一致/不一致」的粗粒度反馈——这已是 Seedlang 录音对比的 80% 体验。
- **风险**：WASM 模型体积与加载时长，P3 阶段先用 1 个页面做技术验证再决定是否铺开。

### 10.4 LLM 增强（P3，全部可选、全部走服务端代理）

按价值排序：① 写作批改（用户写 5 句话日记 → 语法批改 + 错误分类，参考 DeutschPath）；
② 语法点「追问讲解」（对现有 36 个专题做 AI 答疑）；③ 情景对话。
**没有后端之前一律不做**，避免 API key 进客户端。
